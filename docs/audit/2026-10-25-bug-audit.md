# 当前项目 Bug 审计

日期：2026-10-25（Asia/Shanghai）。源码基线：`main@f1a205be2a747c6d0107ba4be1e54ee89bce2c05`。

这是本地优先的个人物品管理 PWA，包含购买成本、生命周期、备份、可选多设备同步及 AI 辅助填表。本轮按一人使用、偶尔切换浏览器或设备的实际规模审计，重点检查输入和页面状态边界。

审计结论：确认 **4 个可复现的 P2 问题**，优先处理金额丢失和返回丢草稿。审计时 852 项测试与正式构建通过，不能据此认为页面交互没有缺陷。下文保留当时的复现和原因；用户随后授权修复，进展与验证见文末。

## 1. 金额框接受的内容，保存时可能被静默清空

- **位置**：`src/pages/ItemFormPage.tsx:256`、`:286`；`src/domain/purchase.ts:154`。相同解析模式还出现在 `src/components/ConvertToOwnedSheet.tsx:73` 与 `src/components/DisposalSheet.tsx:64`。
- **用途**：购买价格和附加花费由受控输入框收集，保存时转换为整数分。
- **问题与复现**：编辑一件原价格为 123.45 元的隔离测试物品，将购买价格替换为 `.5`，界面接受该文本，保存按钮可用；保存后价格为 `null`，没有格式错误提示。输入 `12.` 同样保存为空；对照输入 `0.50` 正确保存为 50 分。
- **原因**：输入正则允许小数点前或后的数字暂时为空，提交解析器要求两侧都有数字；提交时没有区分“用户未填”和“非空但解析失败”。
- **最小修复**：在三处金额提交流程中拒绝非空但解析失败的字段，显示对应错误并保留输入；若产品要接受 `.5`、`12.`，先统一标准化后再解析。不要仅把空值写库，也不要扩大 AI 或同步边界的校验宽松程度。
- **不处理的影响**：用户认为已经填入价格，实际记录却没有金额；编辑原有记录时还会清掉旧价格，进而影响资产与日均成本。
- **验证与缺口**：浏览器已验证 `.5`、`12.` 和 `0.50` 的实际持久化结果；转为持有与出售表单目前仅由源码确认同类调用，未另行操作复现。应补非空非法金额的提交回归。

## 2. 浏览器返回绕过未保存确认，前进后草稿丢失

- **位置**：`src/pages/ItemFormPage.tsx:225`、`:637`；`src/components/ItemPanel.tsx:12`。
- **用途**：页面内的取消、返回和面板关闭会检查 dirty 状态，让用户确认是否放弃修改。
- **问题与复现**：从物品详情点击编辑，修改名称为“尚未保存的草稿”。点击页内返回会出现“放弃此次修改？”；选择“继续编辑”后，执行浏览器原生返回则直接回到详情，没有确认。再前进到编辑页，名称恢复为旧值，草稿已丢失。
- **原因**：确认逻辑绑定在页内 `handleBack` 和面板关闭回调，没有覆盖历史记录返回；离开路由后表单组件被销毁。
- **最小修复**：让历史返回也经过未保存检查，或为被历史导航卸载的表单保存并恢复草稿；与现有面板关闭保护复用同一规则，覆盖“继续编辑”和“确认放弃”两条路径。不能只为顶栏按钮增加确认。
- **不处理的影响**：同样的“返回”操作在不同入口下表现不同，填写较长内容后可能直接丢失未保存输入。
- **验证与缺口**：在隔离 Edge 中使用真实的 `history.back()` / `history.forward()` 复现，页内返回作为对照。iPhone 上的系统侧滑仍需真机验证；没有把桌面结果宣称为已测得的 iPhone 行为。

## 3. 关闭同步成功，设置页仍保留开启状态

- **位置**：`src/pages/SettingsPage.tsx:331`、`:418`；`src/features/sync/SyncContext.tsx:48`、`:63`；`src/db/repositories/syncRepository.ts:227`。
- **用途**：关闭同步会清除本设备的认证信息和游标，保留本地业务数据与待发送改动。
- **问题与复现**：在隔离上下文写入合成配对状态，进入设置后点击“关闭同步”。数据库已变为 `enabled=false` 且 `secret=null`，页面弹出关闭成功提示，却仍显示“立即同步”和“关闭同步”，也没有重新粘贴恢复码的入口；刷新页面后入口才正常出现。
- **原因**：处理函数改了数据库和设置页的局部状态，没有刷新 SyncContext 中的摘要。Context 的摘要主要随引擎事件刷新，不会自动监听这次数据库状态变化。
- **最小修复**：在关闭同步成功后刷新 Context 摘要；同时检查备份恢复这条也会禁用凭据的路径，确保其完成后刷新相同摘要。现有 `refresh()` 已可复用。
- **不处理的影响**：用户无法从当前界面准确判断同步是否开启，重新连接入口被错误隐藏，需要手动刷新。**本例实际凭据已经清除，不代表关闭后还在继续上传数据。**
- **验证与缺口**：截图与数据库断言同时确认了显示/存储不一致，刷新后作为对照恢复正常。测试中的本地同步 API 被拦截为合成失败响应，截图里的服务失败文字不是线上服务故障证据；没有连接生产同步空间。

## 4. 不存在或已删除的物品，详情和编辑页无限加载

- **位置**：`src/features/data/hooks.ts:17`；`src/pages/ItemDetailPage.tsx:205`；`src/pages/ItemFormPage.tsx:156`、`:180`。
- **用途**：`useItem` 查询活跃物品，页面需要区分加载、查到记录和查无记录。
- **问题与复现**：打开 `/items/audit-missing`，查询确认没有该物品且 56 个分类已就绪，详情页仍持续显示“正在载入物品”；打开其 `/edit` 路径则持续显示“正在载入表单”。等待后没有“物品不存在”提示。
- **原因**：hook 对查询未完成和最终查无结果都返回 `undefined`。详情页因此一直停在 loading 分支，其不存在提示无法到达；编辑页则始终不能完成初始化。
- **最小修复**：让 hook 区分加载态和未找到态，例如最终未找到返回 `null`；同步更新所有调用方，在编辑页给出未找到提示与返回入口。保留正常的异步加载状态。
- **不处理的影响**：旧链接、已删除记录或其他设备删除后的页面会看起来一直在等待，用户无法知道记录已经不存在。
- **验证与缺口**：详情与编辑两条不存在记录路径均在浏览器复现；通过相同 repository 查询返回空和分类已加载排除了普通启动缓慢。未单独模拟远端删除，但该场景使用同一查询结果分支。
